# PathFlow Official Progress Report Export & Printing Architecture (Phase 13B)

## 1. Overview & Purpose

PathFlow provides an official, deterministic progress report designed for academic review, faculty evaluations, and historical documentation. Phase 13B establishes the print and PDF export pipeline, enabling students and researchers to produce clean, presentation-ready documents directly through browser-native printing without third-party cloud dependencies or bloated PDF binaries.

---

## 2. How Printing & Save as PDF Works

The export mechanism relies on the browser-native printing engine triggered via `window.print()` coupled with a dedicated `@media print` CSS specification:

1. **User Action**: The user selects **Print Report** or **Save as PDF** in the Reports View (`#reports`).
2. **Native Dialog**: The browser opens its standard print preview interface.
3. **PDF Destination**:
   - In modern browsers (Chromium, Firefox, Safari, Edge), selecting the printer destination **"Save as PDF"** or **"Microsoft Print to PDF"** generates a high-fidelity vector PDF file directly on the client machine.
   - Alternatively, selecting a physical printer outputs a paper document formatted to standard A4 specifications.
4. **Deterministic Rendering**: The printed document renders using exact color adjustments (`print-color-adjust: exact`), standard 12mm/15mm page margins, and intelligent page-break protection.

## 3. What is Included in the Printed Report

The printed document preserves all factual, observational sections generated by `ReportService`:

* **Official Header**:
  - PathFlow seal and official document identification.
  - Report title and observational record statement.
  - Generated timestamp (localized ISO 8601 representation).
  - Selected review period (This Week, Last Week, or Custom Range).
  - Active report scope (All Goals, Specific Goal, or Specific Roadmap).
  - System language and calendar configuration.
* **Executive Summary**:
  - Active goals and roadmap counts.
  - Task completion ratios and counts.
  - Selected period planned time vs. actual recorded time.
  - Variance and time completion percentage.
  - Session counts and weekly commitment fulfillment.
* **Goals Breakdown**:
  - Title, description, and status.
  - Lifetime actual time vs. Selected period planned/actual time.
  - Overall lifetime task completion percentage.
* **Roadmaps Breakdown**:
  - Title and parent goal association.
  - Overall progress and completed tasks.
  - Lifetime actual time vs. Selected period planned/actual time.
* **Tasks Record**:
  - Task title, roadmap association, status, and priority.
  - Lifetime actual time vs. Selected period planned/actual time.
  - Session counts and recorded completion dates.
* **Work Sessions Summary**:
  - Total sessions count, duration, and active days.
  - Chronological log of recent sessions (task, roadmap, duration).
* **Weekly Planning Summary**:
  - Total planned commitments, dated commitments, and flexible allocations.
  - Detailed commitment listing with target dates and completion states.
* **Daily Activity Breakdown**:
  - Calendar date and localized day of week.
  - Daily planned minutes, actual minutes, session counts, and completed tasks.
* **Official Footer**:
  - Verification statement.
  - Localized generation timestamp and ISO 8601 UTC deterministic record notice.

## 4. What is Intentionally Excluded

To ensure the exported document is a formal record free of application UI clutter, the following elements are excluded via `@media print`:

* **Application Navigation**: Sidebar navigation, brand headers, mobile drawer backdrops.
* **Top Header & Chrome**: Navigation breadcrumbs, active timer tickers, menu buttons.
* **Interactive Controls**: Period switcher tabs, date picker inputs, scope dropdowns, refresh buttons.
* **Export Action Buttons**: "Print Report" and "Save as PDF" buttons.
* **Editing & Mutating UI**: No form inputs, select controls, or interactive state toggles.
* **Subjective Evaluation**: No productivity scores, performance ratings, rankings, AI judgments, or speculative projections.

---

## 5. Client-Side, Local-First Architecture

* **Zero Server / Backend Required**:
  The report is generated entirely in-memory within the client application by querying local IndexedDB repositories through `ReportService`. No data is transmitted to an external service or cloud renderer.
* **Pure Read-Only Operation**:
  Exporting or printing does not alter application state, create sessions, modify tasks, mutate weekly plans, or update user preferences. It is an idempotent, non-destructive read-only operation.
* **Offline Operation**:
  Because both data storage and rendering occur locally, users can generate and save PDF reports while completely disconnected from the Internet.

## 6. Language & Calendar Behavior

The print export honors the user's active preferences seamlessly:

| Configuration | Output Behavior |
| :--- | :--- |
| **English + Gregorian** | Left-to-Right layout, Gregorian calendar dates (e.g., "Sep 24, 2026"), Western Arabic numerals (0–9). |
| **English + Persian** | Left-to-Right layout, Solar Hijri (Jalali) calendar dates (e.g., "Mehr 2, 1405"), Western Arabic numerals. |
| **Persian + Gregorian** | Right-to-Left (RTL) layout, Gregorian calendar dates, Eastern Arabic / Persian numerals (۰–۹). |
| **Persian + Persian** | Right-to-Left (RTL) layout, Solar Hijri calendar dates (e.g., "۲ مهر ۱۴۰۵"), Eastern Arabic / Persian numerals. |

Typography, text alignment, and table headers automatically adapt to RTL/LTR directionality. All report labels and section headers originate from the centralized translation dictionary (`src/app/preferences/translations.ts`), preventing hardcoded text.
